# EBR-106: Footprints and extendable ground

**Design only**, based on main `86f2b44` and Engineer 2's grid note. The first two slices preserve the island and appearance, without expansion. Content stays plain data, art stays in render factories and `src/content/slots.ts`, and `src/main.ts` stays untouched.

## Placeable data and rotation

Add a `PLACEABLES` registry in `src/content/`. Each entry has a unique `id`, render `assetId`, visual `size` in world units `[width,height,depth]`, a `footprint` of integer `[column,row]` offsets (any shape, including holes), `anchor`, `blocking: solid | walkable`, and `blocksPlacement`. Size describes visual bounds, not cells, and never rescales the asset. `visualOffset` positions the existing asset base-root from the mask's bounding-box center. A solid item's walking collider is its cell union or an explicit box local to that root; a walkable item has none. `blocksPlacement` independently controls reservation against later items.

Illustrative data (the L is test data only, not a new asset or UI entry):

```json
[
  {"id":"fence", "assetId":"fence", "size":[1.47,0.95,0.215], "footprint":[[0,0]], "anchor":[0,0], "visualOffset":[0,0,0], "blocking":"solid", "blocksPlacement":true, "collider":{"type":"box","width":1.47,"depth":0.26}},
  {"id":"plot", "assetId":"plot", "size":[2.94,0.31,1.44], "footprint":[[0,0],[1,0]], "anchor":[0,0], "visualOffset":[0,0,0], "blocking":"walkable", "blocksPlacement":true, "collider":{"type":"none"}},
  {"id":"example.l", "assetId":"example.l", "size":[3,1,3], "footprint":[[0,0],[0,1],[1,1]], "anchor":[0,0], "visualOffset":[0,0,0], "blocking":"solid", "blocksPlacement":true, "collider":{"type":"cells"}}
]
```

`anchor` is the offset from the unrotated mask's minimum corner to its reference cell; relative footprint offsets have component-wise minimum `-anchor`. Validate nonempty, unique, safe-integer cells, safe-integer anchors, finite positive sizes, unique IDs and consistent collider/blocking fields. The reference need not be occupied.

Each placed instance stores its registry ID, selected cell `A`, and quarter-turn `q = 0..3` (initially 0). Columns increase along +X, rows along +Z. Apply `R(c,r) = (r,-c)` `q` times, matching positive Three.js Y rotation. For each rotated offset `p`, the world cell is `A + p - min(rotated mask) - anchor`, with component-wise minimum and `A` unchanged. Sort cells by column then row, as today. The fixed offset from the bounding corner stays at `A`; this is not a pivot about a fixed occupied cell. The asset root is the resulting bounding rectangle's center plus rotated `visualOffset`, yaw `q × π/2`. The plot is `[[0,0],[1,0]]` at even turns and `[[0,0],[0,1]]` at odd turns relative to `A`, as today. The L at `q=1` is `[[0,1],[1,0],[1,1]]`; its corner remains empty. Four turns restore the mask and anchor.

The fence reserves a full tile but keeps today's narrow 1.47 × 0.26 walking box, rotating with its visual. The plot reserves two tiles but is walkable. Existing IDs, transforms, visual factories, materials and placement results remain unchanged.

## Ground cells and extension

Define chunk data in `src/content/` and a ground service exposed as `groundGrid` in `src/app/` context, separate from the ground mesh. `app/scene` creates it; in slice 2 `app/placement` binds the index after farm, garden and character registration. Keep `T = 1.5` and origin `(-7.5,-7.5)`: cell `[c,r]` covers `[originX+cT, originX+(c+1)T)` × `[originZ+rT, originZ+(r+1)T)`. `cellAt` uses floor; signed coordinates never shift when ground grows.

Chunks have an `id`, land rectangles with world X/Z `min`, `max`, `height`, and disjoint cell ranges with integer `min`, `maxExclusive`, `terrain` (a 1 × 1 range adds one cell). `island-0` has land `{min:[-8,-8], max:[8,8], height:2.4}` and cells `{min:[0,0], maxExclusive:[10,10], terrain:"free"}` before overlays. Its original 16-unit top, underside, stairs and seeded cliff ring remain byte-identical. The surrounding 0.5-unit strips are visible supported land, but unbuildable. An absent cell is `void` for placement, even where it contains an old edge strip; physical support is a separate query.

Each cell exposes base terrain (`free`, `path`, `water`, `locked`, or implicit `void`) and a set of object/keep-out IDs. Effective-state priority is `void`/`locked`, `blocked` by a non-plot placement blocker, `plot`, `water`, `path`, then `free`; removing an occupant retains the underlying terrain. Water keep-outs classify as water, not generic blockers. `free` and `path` allow placement; the other states do not. Walking uses land support and continuous colliders: bridge and sheepfold reservations can block placement but permit walking. Label tiles touched by the authored path ribbon as path; derive water labels from existing pond/stream keep-outs, not the wider visual outline.

The service offers `cellAt`, `getCell`, `addChunk({id, land, cells})`, land/support bounds and change notification. Addition atomically rejects duplicate IDs/cells, preserves coordinates and requires the land union to cover each newly enabled full tile. Cell `[10,0]` spans X `[7.5,9]`, Z `[-7.5,-6]`: old land supplies X `[7.5,8]`, an adjoining region must supply `[8,9]`. Bounds are only an envelope; support and exposed edges use the land union. The extension test adds cells in memory, without rendering or unlocking a larger map.

Once consumers migrate, adding chunk/cell data needs no item-specific or scene-code changes. The ground adapter updates raycastable tops and exposed perimeter, suppressing internal cliffs; `island-0` alone keeps the existing geometry, side order, seeds and materials. Camera follow keeps its unclamped focus and 20-unit view; on change it reads the support envelope and enlarges the far plane only if needed for the followable area. Character-shadow support reads the land/stair union plus the bridge rule; waterfall shadow/cliff consumers read the outlet's owning exposed edge, not a global maximum. Movement, routing, weather and path/water edges also use shared bounds/support or their owning chunk's edge. Reject live extension across stairs or waterfall until an approved migration policy; new seams and rims require Look Dev approval.

## Placement, occupancy and collisions

Index each cell to a **set** of owner IDs; entity/obstacle records are authoritative. Index a placed item's exact rotated mask, not its bounding rectangle, visual overhang or walking collider. Index static scenery wherever its existing box/circle intersects a cell, using today's strict box-overlap and circle-touch rules. Update changed sources; overlapping owners survive independent removal.

`createFarmLayout` supplies tree circles, building and coop/ramp boxes, pond, stream and walkable bridge; `app/farm.ts` adds sheepfold fence, shelter, sheep and placement-only pen shapes; `app/garden.ts` adds hive boxes (flowers are scenery). `createCharacterController.syncObstacles` registers these ECS obstacles. The placement adapter also syncs decoration `Box3` keep-outs and the live player. Preserve all sources, including `blocksWalking: false` bridge/pen reservations; moving blockers and the player must stay current. Placed fence obstacles belong to their ECS entities; the scene array mirrors those fences for compatibility. A solid cell-union collider creates one owner-linked obstacle entity per occupied cell; removal deletes them. An explicit box stays on its owner; a walkable item adds none. Movement and routing use these continuous shapes, never full-tile approximations of legacy colliders.

Validate each mask cell against ground, owners with `blocksPlacement`, current obstacle/decorative shapes and the player; the candidate is valid only if all cells are valid. Keep the untinted 50% asset ghost, olive/rust 50% washes, lifts and render order from placement slots/geometry. Paint exact cells: reuse the single wash for homogeneous fence/plot rectangles, use non-overlapping washes for non-rectangular or mixed masks, and keep the named `placement-wash` invalid-colored for existing consumers. Preserve reason priority (outside, occupied, farm object, player), R/Rotate, mouse click/Enter/Place, touch/pen preview before Place, and Esc/Cancel. Revalidate on confirm, then atomically create entity, ownership and walking collider. Removal from any occupied cell clears all owner cells/colliders; undo remains latest-first. An L's hole is not occupied.

## Asset Forge contract

The Forge spec has `size`; its recipe's `footprint: {w,d}` is **world dimensions**, not cells, and its verifier measures mesh bounds. A future approved bundle emits versioned placement metadata/sidecar: asset ID, unrounded local bounds, optional cell offsets and anchor, blocking rule and `blocksPlacement`. Do not silently add fields to the closed recipe schema. Bounds yield visual size; retain the base-center root and +Z facing.

Without explicit cells, reserve `ceil(max(bounds.width, recipe.footprint.w)/T)` columns by `ceil(max(bounds.depth, recipe.footprint.d)/T)` rows, at least one each, anchored `[0,0]`. Center measured X/Z bounds using a local `visualOffset`; rotate offset, mask and collider together. Odd turns swap dimensions. An author can supply the registry's explicit relative cells and anchor, including holes, instead of a rectangle. Validate IDs, bounds, cells and flags; flag visual/collider overhang for review. A recipe box maps to a solid box collider; `none` maps to walkable. `blocksPlacement` defaults to true. Current Forge H10 still requires a box: accepting `none` or cell metadata needs an explicit schema/verifier change and normal bundle/Look Dev signoff.

## Slices and gates

1. **Data first:** add registry and ground/occupancy API; port fence/plot, deriving legacy rectangle values from the registry. Unit-test rotations, an L blocking exactly its cells and not its hole, overlapping owners, edges, and extension adding cells without moving existing ones. Run `npm run build`, `npm test` and `tests/browser/scene-data.browser.mjs`; compare the complete scene dump, including previews, byte-for-byte with `86f2b44`. No terrain remesh, ghost/UI, obstacle registration, walking/routing, camera, shadow, save or map changes.
2. **Consumers:** migrate placement, exact-cell ghost/validation and collider ownership; index legacy obstacles as above. Resolve validated registry IDs rather than shape switches; retain only fence/plot controls. Gate on build and existing placement, walking, routing, stairs, water and browser tests; add mixed-validity/L-hole, rotation, player recheck, removal and undo tests. Same-pose, same-seed default-scene comparison against `86f2b44` must have **0 changed pixels**, unmasked; homogeneous legacy previews retain their signed look. Mixed-cell feedback is the only intended preview behavior change.
3. **Later, separately approved:** connect terrain rendering/bounds consumers for growth; gate on seam/support/shadow/routing tests and Look Dev review before any visible expansion. `SaveV1` is only a snapshot hook today, rejects new kinds and negative cells, and remains unchanged in slices 1–2. A later SaveV2 stores chunk/base-terrain data and ordered placed IDs/kinds/anchors/rotations, not derived occupancy; rebuild occupancy/colliders and map V1 cells to anchors in `island-0` while preserving player, clock, weather and order. Gate on migration and JSON round trips. Forge integration separately gates on schema, bounds/explicit-mask tests and signoff.

Risks are the non-tile-aligned old rim, changed boundary/tangency behavior, stale or double-counted blockers, and confusing visual size with collision or reservation. No look retuning, new map area, asset promotion, unlock/economy or new Build UI is in these slices.
