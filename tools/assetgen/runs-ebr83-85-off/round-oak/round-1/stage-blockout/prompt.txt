## 1. Style rules to enforce

### 1.1 Pixel-pass math (so "visible" is measurable)
View height is 20 world units rendered at 180 px, so **1 world unit = 9 px** at the pixel-pass resolution (320×180, each pixel shown as 4 CSS px).
- 0.11 units = 1 px (the floor; anything thinner is invisible or shimmers).
- 0.2 units = 2 px (a feature meant to be seen).
- 0.3 units = 2.7 px (a part that must read as its own shape, such as a handle, a window or a wheel).

### 1.2 Silhouette and chunkiness
1. Silhouette first. The asset must be recognisable as a **solid black shape at 320×180**, in the game isometric view and from the front and side.
2. Chunky, toy-like, slightly rounded. 3–6 major masses per asset. Prefer exaggerated proportions to fine detail.
3. Thinnest solid dimension ≥ **0.1** (rails and planks may be 0.1 thick if they are ≥ 0.13 tall or wide). Cleats, bands and twine may be 0.1 wide. Nothing is thinner than 0.1 anywhere.
4. Every part meant to read has a smallest dimension ≥ **0.2**; handles, wheels, windows and hats ≥ **0.3** in at least two dimensions.
5. Slight hand-made irregularity (a leaning post, a rotated plank, an uneven crown). Seeded and deterministic. Keep it ≤ ~0.03 units and ≤ ~5° so it reads as charm, not damage.
6. Round things use 6–8 segments. Smooth, high-segment spheres and cylinders are rejected as "plastic".

### 1.3 Faceting, shading and tones
- Flat shading, matte (`roughness` 1). No textures, gradients, normal maps, noise, text or alpha cards.
- Each material family uses **at most 3 albedo tones**: base, a lighter tone for tops and edges, and a darker tone for undersides and trim. The scene lights add the lit/shade split on top.
- Never bake light direction or shadow into the colours. The key light is fixed (EBR-80): from screen upper-left, slightly behind. The asset must not fight it.
- **No outline.** The game has no outline today (EBR-53 may add a post-process one). Do not fake outlines with black meshes or back faces. Separate shapes by value and hue instead.
- No shadow maps, no lights and no cast-shadow tricks inside an asset. Ground contact shadow is added by the game as an offset blob.

### 1.4 Palette families
Use palette keys, not hex literals. Allowed families:
- **Greens:** foliage dark / mid / light, grass.
- **Warm woods and soil:** barn wood, coop wall, trim, door, trunk, dirt, dirt edge, dirt highlight, timber.
- **Rust roofs:** roof, shingle.
- **Cream:** plaster.
- **Warm stone:** `building.stone`.
- **Water:** pond water, rim, deep. Glass.

**Approved extension tokens** (design values; all other additions need written Look Dev approval):
| token | hex | use |
|---|---|---|
| `flower.red` | 0xc75b46 | flowers, mushroom caps, berries (existing comb colour) |
| `flower.yellow` | 0xf2c94c | flowers |
| `flower.blue` | 0x6a8fd0 | flowers (small clusters only) |
| `flower.orange` | 0xe08a3c | flowers, small mushrooms |
| `pumpkin` | 0xd9822b | pumpkins |
| `wool` | 0xf3ead6 | sheep wool, hat band, sack |
| `metal` | 0x554433 | axe head, bucket hoops, wheel rim, lantern frame (existing lantern metal) |
| `lantern.glow` | 0xffb060 | lantern glass only (see below) |
Mushroom stems and sacks reuse `plaster`. Straw reuses `dirt highlight`.

**Forbidden hues:** pure black, pure white, grey-blue (except stone, glass and water), saturated blue, purple, magenta or cyan, neon or acid green, chrome and metallic sheen, and any hue that makes the asset glow or look wet. The sole emissive is `lantern.glow`, declared on the lantern glass, ramped by the existing night amount, with no PointLight.

### 1.5 Worn vs clean
**Lightly weathered, never dirty.** Clean, readable forms plus 1–2 wear cues per asset: a lighter edge band, one darker or patched plank, a chipped rock facet, a leaning post. No grime, cracks, rust textures, decals or moss textures. Moss is a `foliage dark` cap mesh.

### 1.6 Foliage and nature look (from the Daniil frame)
- Round trees: crowns are **clusters of 3–6 flat-shaded lobes** of varied size, in foliage mid/light/dark, with the lightest lobe on top-left. Not one smooth ball.
- Pines and firs: **3–4 stacked cones**, each slightly smaller, offset and rotated by a few degrees. Dark green family only.
- Bushes: 2–3 lobes, optionally 3–5 small `flower.red` berries (≥ 0.15).
- Rocks: faceted, warm-grey (`stone`), one lighter top facet, optional `foliage dark` moss cap.
- Flowers: chunky heads (≥ 0.15), stems short. One accent colour per patch, plus an optional second.
- Grass tufts: a few dark-green blades (≥ 0.11 wide), grouped. Grass blades are a big part of the reference's cozy look.

Each axis is scored 1–5. **SIGNED needs every axis ≥ 4 and no REJECT reason.** Otherwise I return named changes.

| Axis | 5 looks like | Auto-fail if |
|---|---|---|
| Silhouette | recognisable at 320×180 as a solid shape, from front and side | unreadable at pixel-pass size; reads as a different object |
| Shape language | chunky, toy-like, faceted; matches the cottage, coops and trees | smooth, plastic, spiky, over-detailed, or realistic |
| Palette | only palette keys and approved tokens; warm, cozy | any forbidden hue; raw hex; glow without a declared source |
| Value structure | lit top / mid side / dark underside under the game key light | flat, or lit side on the wrong side, or too dark to read |
| Scale and fit | correct against character, fence and cottage; sits on the ground | wrong by more than ~25% of the table in 1.7; floating or buried |
| Craft | clean joins, no flicker, no gaps, no tiny floaters, 1–2 wear cues | z-fighting, holes, parts thinner than 0.1, unconnected parts |

### REJECT reasons (any one rejects the asset)
1. Off-palette colour, or a forbidden hue.
2. Looks like a different art style next to the signed cottage, coops, fence and trees (this is the most common failure and the one automation misses).
3. Detail that disappears at the pixel pass, or a silhouette that is only readable when zoomed in.
4. Smooth organic geometry, plastic spheres, or a realistic model.
5. Floating, buried or overlapping parts that read as a mistake.
6. Over budget (triangles, colours) or any hard check failing. A numerically passing asset can still be rejected by eye.
7. Shading that contradicts the key light (a front-lit face that should be in shade).
8. A baked outline, text, decal or texture.
9. Wrong scale against the table in 1.7.
10. A copy of another asset with a different colour (variants must differ in silhouette).

- **Night:** an asset must not glow. Only the lantern post glass may be lit at night. Everything else must stay readable against the void and ground by value alone.
- If the critic or the checks say PASS and my eye says no, the asset is REJECTED. The automated gates are a floor, not an approval.

# Asset Forge style bible

**Draft for Look Dev and QA.** The authority is Look Dev's 2026-11-06
`ASSET-BRIEF.md`; PM's recipe, four-round and no-animal rulings take precedence
for this PR. Its numbers are design values, not
measurements from the Daniil frames. The machine-readable block below is the

## Shape, scale and materials

The farm is a warm, cozy, chunky toy diorama: slightly rounded masses, a few
broad flat-shaded facets, deliberate small irregularities and no random noise.
Prioritise the silhouette and 3–5 identity features over decoration. At
1280×720 the game renders the world at 320×180 then enlarges it to 4 CSS pixels
per world pixel: 1 unit = 9 render pixels; 0.11 is ~1 pixel, 0.2 ~2 pixels,
and 0.3 ~2.7 pixels. Nothing, including cleats and bands, may be thinner than
0.1 units. Readable parts should be at least 0.2 units thick; handles, wheels,
windows and hats need at least two dimensions of 0.3. Rails/planks may be 0.1
thick if their other cross-section dimension is at least 0.13. Do not
put hairline grain, text, tiny nails, separate leaves, textures or bitmap art on
assets. Use opaque flat-shaded matte materials (roughness 1, metalness 0);
water/glass may be 0.25–0.7. Use 3–6 major masses, 6–8 segments for round
parts, and 1–2 geometric wear cues. No new lights, baked lighting, fake
outlines, textures, transparency, gradients, noise or shadow maps.
Use at most three albedo tones per material family; never bake a light direction
into those colours. Ground contact shadows are supplied by the game.

Reference scales from actual code: character capsule 1.4 high, radius 0.4;
placement tile 1.5; existing fence 1.47×0.17×0.95; cottage walls 4.4×3×2,
chimney top 3.6; coop body 1.4×1.3×1.1 with a raised floor and ramp; signed
tree approximately 2.8 high. Expected heights: bucket 0.4, barrel 1.0,
crate 0.7, hay 0.6, trough 0.5, bench 0.8, wheelbarrow 0.7, well 1.6,
scarecrow 1.8, lantern 1.8, mailbox 1.2, sign 1.3, flower patch 0.3, rock
0.3–0.8, bush 0.7, oak 2.6–3.6 and pine 3–4.2.

Every recipe has a base-centred origin at (0,0,0), +Y up, and front +Z. Its
declared footprint and height must agree within 10% with both the spec and the
built bounds. Nothing may sit below -0.01; every part must connect to the
ground or another connected part. Face direction is a semantic claim: numerical
checks cannot prove a door or handle actually faces +Z.

## Closed recipe vocabulary

The runtime source of truth is declarative JSON: a named part, primitive,
dimensions, transform, palette token and identity-feature tag. No arbitrary
code, external assets, URLs, textures, or raw colour hexes in recipes. Allowed
primitives: `box`, `cylinder`, `cone`, `sphere` (faceted
icosahedron detail 0–1), `capsule`, `wedge`, `lathe` and `extrude`. A bounded
`custom` BufferGeometry array is an explicit lower-trust escape hatch, never
an exemption from checks or human review. At most 40 parts; no nonuniform
transform scale above 1:3. Optional jitter must specify a seed and stay within
0.03 units/radians. Use enough separation or overlap to avoid coplanar faces;
an explicitly declared polygon offset is recorded and subject to review.

Allowed albedo tokens are defined in `src/assets/palette.ts` using the exact
game constants from `src/scene/farmPalette.ts` and
`src/scene/farmBuildingMaterials.ts`. They include `foliage.mid/light/dark`,
`trunk`, `wood.light/mid/dark`, `timber`, `door`, `dirt`, `dirt.edge`,
`dirt.hi`, `plaster`, `roof`, `roof.band`, `stone`, `glass` and
`water`, `water.rim`, `water.deep`. They can be resolved through named slots
for later retinting. Look Dev explicitly approves `flower.red`, `flower.yellow`,
`flower.blue`, `flower.orange`, `pumpkin`, `metal`, and `lantern.glow`; use
each only for its stated purpose in `ASSET-BRIEF.md`. `wool` is approved in
the brief but **out of scope in this PR**, along with animals (EBR-70).
All other extensions require written approval. Normally use one flower accent
per patch; a second is optional. No pure black/white, magenta, purple, neon,
chrome, metallic sheen or unrelated saturated blue/cyan. Only lantern-post
glass may declare `lantern.glow`, night-ramped, without a PointLight.

Signed references to retrieve: `src/scene/createFarmLayout.ts` (trees),
`src/scene/createCottage.ts`, `src/scene/createRampCoop.ts`,
`src/placement/createPlacementVisual.ts` (fence), and
`src/scene/createStoneStairs.ts`. Existing signed assets predate this contract:
some contain translucent ground shadows, prelit/interpolated stair colours,
polygon offset, and small details. Do not silently reinterpret those as allowed
recipe colours or as evidence that a new recipe passed a rule.

## Stages, checks and review

Run blockout, form, palette/material, detail, in-scene lighting and optimisation
in that order. Every stage requires H1–H10 before fixed-camera render feedback
and an independent OpenCode critic. A rendered identity feature that cannot be
seen is a blocker even if the overall score is high. A pixel-difference test can
measure the visible contribution of each tagged part (not just the combined
feature), but **cannot prove that a
tag is truthful**; the vision critic and human must judge semantic identity.
Fixed renders use eight 45-degree yaws, three game light phases and grass,
path and void backgrounds. Each frame has a hash; QA also requires morning and
night-rain assessment and in-game placement before final signoff. The generator
and critic receive the full REJECT rubric and the signed cottage/coop/fence/tree/
stairs anchors. Anti-examples are a smooth sphere tree, spiky rock and
off-palette barrel; numeric heuristics cannot replace Look Dev's eye.

| Hard gate | Meaning |
| --- | --- |
| H1 | Closed schema, allowed primitives and palette tokens. |
| H2 | Part and triangle budgets. |
| H3 | Bounds and metadata within 10% of the brief. |
| H4 | Base-centred origin, ground contact and declared +Z front. |
| H5 | Minimum 0.1 thickness everywhere, 0.2 readable parts, 0.3 handle/wheel/window/hat faces. |
| H6 | Two builds have identical geometry/material hashes. |
| H7 | Detect near-coplanar overlap; signed references can have analytic warnings, and empirical flicker is a failure. |
| H8 | All parts connected to each other or ground. |
| H9 | Nothing below -0.01 for new assets. |
| H10 | Collision footprint is 90–130% of the declared footprint. |

Soft checks include at least 40 changed pixels per silhouette at game scale;
contrast against grass/path/void of at least 1.15 luminance ratio or a
meaningful hue difference; key-light/three-step value agreement, night glow,
scene scale and style distance. These are design floors, not measurements or
proof of quality. The vision critic's separate session scores silhouette,
palette, shape language, value structure, scene fit and craft 1–5 and names
blockers/fixes. If image reading or critique fails, the report must say
**visual critique not run**; a numeric-only check is not a visual pass.

At most four candidate rounds, with bounded corrections per stage and globally.
Record `continue`, `refine-spec`, `refine-code`, `request-input` or `stop`,
source/recipe, checks, renders, critique and the best-so-far candidate. The
candidate reaching the cap remains `needs-human`, is listed separately with
its renders, and cannot enter the bundle. Only `PASSED` candidates may be
bundled, and actual in-game assets still require Look Dev signoff. An independent
critic session is not independent artistic approval.

RECIPE CHEAT SHEET:
# Asset recipe cheat sheet

Return **JSON data**, not TypeScript or code. Every part must use a palette
token and may tag exactly one declared identity feature. Use several parts
with the same feature tag if that feature needs several components. The checker
tests each feature's visible contribution in eight fixed daytime views.

```json
{
  "id": "example",
  "category": "prop",
  "footprint": { "w": 1, "d": 1 },
  "height": 1,
  "origin": "base-center",
  "facing": "+Z",
  "parts": [
    { "name": "body", "prim": "box", "size": [1, 1, 1], "at": [0, 0.5, 0], "mat": "wood.mid", "feature": "body" }
  ],
  "anchors": {},
  "emissive": [],
  "collision": { "type": "box", "w": 1, "d": 1, "h": 1 },
  "slots": {},
  "tags": ["farm", "cozy"]
}
```

Primitive fields (all position/dimension units are world units; rotations are
Euler **degrees**; dimensions are full widths):

* `box`: `size:[width,height,depth]`.
* `cylinder`: `radiusTop`, `radiusBottom`, `h`, `segments` (6–8; both radii positive).
* `cone`: `radius`, `h`, `segments` (6–8); the builder makes a nondegenerate tip.
* `sphere`: faceted icosahedron, `radius`, `detail` (0 or 1).
* `capsule`: `radius`, `length` (straight middle), `segments`.
* `wedge`: `size:[width,height,depth]`.
* `lathe`: `profile:[[radius,localY],...]` ordered from bottom to top, `segments`.
  A zero-radius endpoint is supported. For a closed barrel, use e.g. axis point,
  base rim, middle bulge, top rim, axis point. The local y values are relative
  to `at`, not absolute world coordinates.
* `extrude`: `polygon:[[x,y],...]`, `depth` along Z.
* `custom`: `positions` and triangle `indices`; lower-trust, only when necessary.

Each part needs `name`, `prim`, `mat`, `at`; optional `rot`, `scale`, `feature`,
`exception` (`band` or `cleat` only; still at least 0.1), `polygonOffset`, and seeded `jitter`.
No loops, calculations, expressions, URLs, comments, raw hexes, arbitrary keys,
or code. Matte albedo tokens include `wood.mid`, `wood.light`, `timber`,
`trunk`, `foliage.mid`, `foliage.light`, `foliage.dark`, `dirt.hi`, `stone`,
`plaster`, `roof` and `water`. `slots` can map aliases to these tokens.

The checker uses actual 3D triangle intersection, so intersect adjacent parts by
more than 0.005 units; avoid coincident exterior faces and thin decorative
plates. A valid component must be connected to ground through other components.
Do not use identical X/Z extents on intersecting stacked boxes: their side faces
become coplanar. For a band around a cylinder, use a lathe profile rather than a
solid cylinder if it would hide the body. Use broad readable geometry; do not
claim a feature merely by naming an invisible or irrelevant part.

function createPath(group: THREE.Group) {
  const path = new THREE.Group();
  path.name = 'farm-path';
  group.add(path);
  const points = [
    [-3.4, -1.3], [-2.5, -1.22], [-1.6, -1.1], [-0.75, -0.65], [0, 0],
    [0.85, -0.2], [1.6, -0.9], [2.5, -1.7], [3.4, -1.93], [4.3, -1.95],
    [5.15, -1.65], [6, -0.9], [7.6, 0.4], [8.7, 1.35],
  ];
  // One continuous S-shaped route runs from the barn, past spawn and the pond,
  // to the island edge. The outer ribbon is the darker soil border.
  const curve = new THREE.CatmullRomCurve3(points.map(([x, z]) => new THREE.Vector3(x, 0, z)));

  function ribbon(width: number, height: number, color: number, name: string) {
    const material = new THREE.MeshStandardMaterial({ color, roughness: 1 });
    const vertices: number[] = [];
    const indices: number[] = [];
    const segments = 200;
    const edge = GROUND_SIZE / 2;

    for (let i = 0; i <= segments; i++) {
      const t = i / segments;
      const point = curve.getPoint(t);
      const tangent = curve.getTangent(t);
      const halfWidth = (width + 0.08 * Math.sin(t * Math.PI * 5)) / 2;
      const nx = -tangent.z * halfWidth;
      const nz = tangent.x * halfWidth;
      vertices.push(
        THREE.MathUtils.clamp(point.x + nx, -edge, edge), height, THREE.MathUtils.clamp(point.z + nz, -edge, edge),
        THREE.MathUtils.clamp(point.x - nx, -edge, edge), height, THREE.MathUtils.clamp(point.z - nz, -edge, edge),
      );
      if (i < segments) {
        const a = i * 2;
        indices.push(a, a + 2, a + 1, a + 1, a + 2, a + 3);
      }
    }

    // Tight bends can fold the inside edge of the ribbon. Keep every
    // nondegenerate triangle front-facing from above before computing normals.
    for (let i = 0; i < indices.length; i += 3) {
      const a = indices[i] * 3;
      const b = indices[i + 1] * 3;
      const c = indices[i + 2] * 3;
      const normalY = (vertices[b + 2] - vertices[a + 2]) * (vertices[c] - vertices[a]) -
        (vertices[b] - vertices[a]) * (vertices[c + 2] - vertices[a + 2]);
      if (normalY < 0) [indices[i + 1], indices[i + 2]] = [indices[i + 2], indices[i + 1]];
    }

    const geometry = new THREE.BufferGeometry();
    geometry.setAttribute('position', new THREE.Float32BufferAttribute(vertices, 3));
    geometry.setIndex(indices);
    geometry.computeVertexNormals();
    const mesh = new THREE.Mesh(geometry, material);
    mesh.name = name;
    path.add(mesh);

    // Round the barn end; the other end meets the edge of the island.
    const [endX, endZ] = points[0];
    const end = new THREE.Mesh(new THREE.CircleGeometry(width / 2, 20), material);
    end.rotation.x = -Math.PI / 2;
    end.position.set(endX, height + 0.001, endZ);
    path.add(end);
  }

  ribbon(1.34, GROUND_HEIGHT + 0.02, FARM_PALETTE.dirtEdge, 'farm-path-edge');
  ribbon(1.2, GROUND_HEIGHT + 0.024, FARM_PALETTE.dirt, 'farm-path-surface');

  const highlight = new THREE.MeshStandardMaterial({ color: FARM_PALETTE.dirtHighlight, roughness: 1 });
  for (const [index, t] of [0.055, 0.1, 0.145, 0.19, 0.235, 0.28, 0.33, 0.39, 0.46, 0.53, 0.61, 0.7, 0.8, 0.9].entries()) {
    const point = curve.getPointAt(t);
    const tangent = curve.getTangentAt(t);
    const offset = [0.38, -0.32, 0.18][index % 3];
    const x = point.x - tangent.z * offset;
    const z = point.z + tangent.x * offset;
    if (Math.abs(x) > GROUND_SIZE / 2 - 0.15 || Math.abs(z) > GROUND_SIZE / 2 - 0.15) continue;
    const dash = new THREE.Mesh(new THREE.PlaneGeometry(index % 3 === 0 ? 0.19 : 0.13, 0.065), highlight);
    dash.name = 'farm-path-highlight';
    dash.rotation.x = -Math.PI / 2;
    dash.rotateZ(Math.atan2(-tangent.z, tangent.x) + (index % 2 === 0 ? 0.2 : -0.2));
    dash.position.set(x, GROUND_HEIGHT + 0.027, z);
    path.add(dash);
  }
}

function createPond(group: THREE.Group) {
  const { x, z, width, depth, waterWidth, waterDepth } = FARM_LAYOUT.pond;
  const pond = new THREE.Group();
  pond.name = 'farm-pond';
  pond.position.set(x, GROUND_HEIGHT, z);
  group.add(pond);

  const outline = [1, 0.96, 1.04, 1.02, 0.95, 1.03, 1.04, 0.95, 1.02, 1.05, 0.96, 1.02, 1.04, 0.96];
  function blob(radiusX: number, radiusZ: number, height: number, color: number) {
    const shape = new THREE.Shape();
    outline.forEach((variation, i) => {
      const angle = i / outline.length * Math.PI * 2;
      const px = Math.cos(angle) * radiusX * variation;
      const py = Math.sin(angle) * radiusZ * variation;
      if (i === 0) shape.moveTo(px, py);
      else shape.lineTo(px, py);
    });
    shape.closePath();
    const mesh = new THREE.Mesh(
      new THREE.ShapeGeometry(shape), new THREE.MeshStandardMaterial({ color, roughness: 0.25 }),
    );
    mesh.rotation.x = -Math.PI / 2;
    mesh.position.y = height;
    pond.add(mesh);
    return mesh;
  }
  const rim = blob(width / 2, depth / 2, 0.027, FARM_PALETTE.pondRim);
  rim.name = 'farm-pond-rim';
  const water = blob(waterWidth / 2, waterDepth / 2, 0.029, FARM_PALETTE.pondWater);
  water.name = 'farm-pond-water';
  const deepWater = blob(0.85, 0.5, 0.03, FARM_PALETTE.pondDepth);
  deepWater.name = 'farm-pond-depth';
  deepWater.position.x = 0.2;
  deepWater.position.z = -0.08;

  const rippleMaterial = new THREE.MeshStandardMaterial({ color: FARM_PALETTE.pondRim, roughness: 0.25 });

    const ripple = new THREE.Mesh(new THREE.PlaneGeometry(length, 0.035), rippleMaterial);
    ripple.rotation.x = -Math.PI / 2;
    ripple.position.set(rx, 0.032, rz);
    pond.add(ripple);
  }
}

      tufts.setMatrixAt(index++, blade.matrix);
    }
  }
